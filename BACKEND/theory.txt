Q- what beginners  do ?  
Ans ->  they simply create an API and remove the user's token from user's side , this is not a good way rather we do it through token blacklisting , 
Loop hole in this method -> 
 for ex - user "Y" do something and by an  accident  he gots the token of user "X" and copied it , kind of hacked "X" user and compromised  , and hence the user "X" log out from all accounts to protect his / her account but we have written the logic in this way that only logged out from the current logged in account , That is why this method is compromised ,  here comes a concept of token blacklisting 
 ---------------------------------------------------------------------------------------------------

 in this  method server maintains a list , literally a blacklist , when the user requests for token delete from cookie , or we can say that log out from current account , that specific token will go into blacklist and whenever the the user "Y" makes request on the basis of user "X"  it detects the same and is deleted once again from that specific "Y" account also , and finally returns 401 unauthorized 

 there are diff diff tools for doing token blacklisting we can do it by redis but here we are doing it through mongodb functionality
